# P2P JSON Protocol — UAV ↔ QGC 通信协议规范

---

## 一、协议概述

P2P JSON Protocol 是一个基于 JSON 格式的轻量级通信协议，用于 UAV（无人机）与 QGC（地面控制站）之间的数据交互。

### 设计目标


| 目标      | 说明                                             |
| --------- | ------------------------------------------------ |
| JSON 格式 | 标准 JSON 文本，易于解析和调试                   |
| 人类可读  | 字段名语义明确，时间格式直观                     |
| 请求-应答 | 支持 REQ → RSP 的同步请求模型，SEQ 号精确匹配   |
| 一对多    | UAV 可与多个 QGC 同时通信，通过 SRC/DST 字段路由 |
| 数据传输  | 通过 Base64 编码承载任意二进制载荷               |

---

## 二、帧格式

### 2.1 消息结构

每条消息为一个完整的 JSON 对象，包含以下字段：


| 位置 | 字段      | 类型         | 必填 | 说明                                  | 示例                                   |
| ---- | --------- | ------------ | ---- | ------------------------------------- | -------------------------------------- |
| 1    | `version` | string       | ✓   | 协议版本号                            | `"1.0"`                                |
| 2    | `src`     | string       | ✓   | 发送方 ID                             | `"uav1"`, `"qgc1"`                     |
| 3    | `dst`     | string       | ✓   | 接收方 ID，`*` 表示广播               | `"qgc1"`, `"*"`                        |
| 4    | `seq`     | uint32       | ✓   | 序列号，MSG 类型固定为 0              | `0`, `10`, `11`                        |
| 5    | `time`    | string       | ✓   | 时间戳，格式`YYYY-MM-DD HH:mm:ss.SSS` | `"2026-08-24 14:30:01.500"`            |
| 6    | `signal`  | string       | ✓   | 消息信号，格式`{模式}.{动作}`         | `"msg.heartbeat"`, `"req.video_start"` |
| 7    | `headers` | object       | ✓   | 键值对，承载参数和响应数据            | `{"status": "ok"}`                     |
| 8    | `body`    | string\|null | ✓   | Base64 编码的消息体，无则`null`       | `null`                                 |

### 2.2 消息结构示意

```json
{
  "version": "1.0",
  "src": "<发送方ID>",
  "dst": "<接收方ID>",
  "seq": <序列号>,
  "time": "<YYYY-MM-DD HH:mm:ss.SSS>",
  "signal": "<模式.动作>",
  "headers": { ... },
  "body": null
}
```

### 2.3 signal 定义


| 前缀  | 含义          | 是否需应答 | 说明                                          |
| ----- | ------------- | ---------- | --------------------------------------------- |
| `msg` | 单向通知/事件 | 否         | 用于心跳、遥测、告警等广播消息                |
| `req` | 请求          | 是         | 必须应答，接收方回复`rsp`                     |
| `rsp` | 应答          | —         | 统一处理成功和失败，通过`headers.status` 区分 |

### 2.4 SEQ 的用法


| signal 前缀 | SEQ 填什么             |
| ----------- | ---------------------- |
| `msg`       | 始终为 0               |
| `req`       | 发送方自增的唯一序列号 |
| `rsp`       | 回填原始请求的 SEQ     |

### 2.5 应答规则

1. **MSG** 不要求应答，SEQ 填 0，可用于广播 (`dst="*"`)
2. **REQ** 必须发给特定目标，接收方必须回复 `rsp`
3. **RSP** 通过 `(src, dst, seq)` 三元组匹配到原始请求
4. **REQ** 发送方需维护超时定时器，超时后视为失败

### 2.6 应答成功/失败

通过 `headers.status` 区分：


| status    | 含义 | 附加字段             |
| --------- | ---- | -------------------- |
| `"ok"`    | 成功 | 按命令携带返回数据   |
| `"error"` | 失败 | 携带`errcode` 错误码 |

### 2.7 错误码


| 错误码 | 说明         |
| ------ | ------------ |
| 100    | 通用错误     |
| 101    | 不支持的命令 |
| 102    | 参数无效     |
| 103    | 超时         |
| 104    | 权限不足     |
| 105    | 资源不可用   |
| 106    | 校验失败     |
| 107   | 设备忙       |
| 108   | 参数超出范围 |

## 三、心跳消息

### 3.1 说明

心跳是 UAV 周期性向所有 QGC 广播的单向消息。信号类型为 `msg.heartbeat`，SEQ 填 0，DST 填 `*`，无需应答。

用于 QGC 实时监控 UAV 的飞行状态、电量、GPS 位置、4G 信号质量等关键信息。

### 3.2 消息定义

```json
{
  "version": "1.0",
  "src": "uav1",
  "dst": "*",
  "seq": 0,
  "time": "2026-08-24 14:30:00.000",
  "signal": "msg.heartbeat",
  "headers": {
    "lat": "31.23",
    "lon": "121.47",
    "alt": "0",
    "signal_4g": "-58",
    "flight_status": "0"
  },
  "body": null
}
```

### 3.3 headers 字段说明


| 字段            | 类型   | 说明              | 示例                       |
| --------------- | ------ | ----------------- | -------------------------- |
| `lat`           | string | 纬度              | `"31.23"`                  |
| `lon`           | string | 经度              | `"121.47"`                 |
| `alt`           | string | 高度（米）        | `"0"`                      |
| `signal_4g`     | string | 4G 信号强度 (dBm) | `"-58"`（-50 强，-100 弱） |
| `flight_status` | string | 飞行状态码        | `"0"`                      |

### 3.4 flight_status 枚举


| 值  | 含义   |
| --- | ------ |
| `0` | 待补充 |
| `1` | 待补充 |
| `2` | 待补充 |
| `3` | 待补充 |
|     |        |

## 四、打开视频（请求-应答）

### 4.1 说明

QGC 向 UAV 发起打开视频推流的请求，信号类型为 `req.video_start`。UAV 收到后启动视频编码推流，并回复 `rsp.video_start` 应答。

### 4.2 请求消息

```json
{
  "version": "1.0",
  "src": "qgc1",
  "dst": "uav1",
  "seq": 10,
  "time": "2026-08-24 14:30:01.500",
  "signal": "req.video_start",
  "headers": {
    "resolution": "1080p",
    "mac": "a1b2c3d4e5f6..."
  },
  "body": null
}
```

#### 请求 headers 字段说明


| 字段         | 类型   | 说明       | 示例                        |
| ------------ | ------ | ---------- | --------------------------- |
| `resolution` | string | 视频分辨率 | `"720p"`, `"1080p"`, `"4k"` |
| `mac`        | string | Message Authentication Code（消息认证码） | `"a1b2c3d4e5f6..."`         |

### 4.3 应答消息（成功）

```json
{
  "version": "1.0",
  "src": "uav1",
  "dst": "qgc1",
  "seq": 10,
  "time": "2026-08-24 14:30:01.800",
  "signal": "rsp.video_start",
  "headers": {
    "status": "ok",
    "stream_url": "rtmp://192.168.1.100:5600/live"
  },
  "body": null
}
```

#### 成功应答 headers 字段说明


| 字段         | 类型   | 说明         | 示例                               |
| ------------ | ------ | ------------ | ---------------------------------- |
| `status`     | string | 固定为`"ok"` | `"ok"`                             |
| `stream_url` | string | 视频拉流地址 | `"rtmp://192.168.1.100:5600/live"` |

### 4.4 应答消息（失败）

```json
{
  "version": "1.0",
  "src": "uav1",
  "dst": "qgc1",
  "seq": 10,
  "time": "2026-08-24 14:30:01.800",
  "signal": "rsp.video_start",
  "headers": {
    "status": "error",
    "errcode": "105"
  },
  "body": null
}
```

#### 失败应答 headers 字段说明


| 字段      | 类型   | 说明                 | 示例      |
| --------- | ------ | -------------------- | --------- |
| `status`  | string | 固定为`"error"`      | `"error"` |
| `errcode` | string | 错误码，参见错误码表 | `"105"`  |

## 六、消息汇总


| 章节 | 消息         | signal            | 方向       | seq | 是否应答 |
| ---- | ------------ | ----------------- | ---------- | --- | -------- |
| 三   | 心跳         | `msg.heartbeat`   | UAV →`*`  | --  | 否       |
| 四   | 打开视频请求 | `req.video_start` | QGC → UAV | --  | 是       |
| 四   | 打开视频应答 | `rsp.video_start` | UAV → QGC | --  | —       |
| 五   | 关闭视频请求 | `req.video_stop`  | QGC → UAV | --  | 是       |
| 五   | 关闭视频应答 | `rsp.video_stop`  | UAV → QGC | --  | —       |

## 七、请求-应答匹配原理

```
QGC 线程1: req.seq=10 video_start  ──────►  UAV
QGC 线程2: req.seq=11 video_stop   ──────►  UAV

         ◄── rsp.seq=11 video_stop  ────────┘  → 匹配 QGC 线程2
         ◄── rsp.seq=10 video_start ──────────┘  → 匹配 QGC 线程1

即使 UAV 回复顺序打乱，SEQ 保证精确匹配。
```

## 八、实现要点


| 关注点    | 建议                                                                            |
| --------- | ------------------------------------------------------------------------------- |
| JSON 解析 | 使用标准 JSON 库解析，通过`signal` 前缀路由消息                                 |
| SEQ 管理  | `req` 用原子递增序列号，`msg` 固定填 0，`rsp` 回填请求的 SEQ                    |
| 超时      | `req` 发送后启动定时器（建议 3-5 秒），超时内部处理                             |
| 广播过滤  | 收到`dst="*"` 的消息全部处理；`dst` 非自身且非 `"*"` 的静默丢弃                 |
| 并发      | UAV 需维护`(QGC_ID, SEQ) → callback` 映射表；QGC 需维护 `SEQ → Future` 映射表 |
| 解析错误  | 丢弃当前消息，JSON 解析失败则跳过，不尝试恢复                                   |
| 扩展性    | 新增命令、新增 headers 字段都不需要改解析器，天然可扩展                         |
