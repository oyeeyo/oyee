### 1.2 协议帧格式

| 起始 | 长度 | 序列号 | 源ID | 目标ID | 消息ID | 保留 | 载荷 | 低校验 | 高校验 |
|---|---|---|---|---|---|---|---|---|---|
| STX | LEN | SEQ | SRCID | DESID | MSGID | RESERVE | PAYLOAD | CKA | CKB |
| 1 | 1 | 1 | 4 | 4 | 1 | 2 | X | 1 | 1 |
| 0xFE | - | - | - | - | - | - | - | - | - |

- `LEN` 只指明 PAYLOAD 长度
- `RESERVE` 2 字节，部分消息被复用为业务字段（如 44 号消息用其承载 logo / 柜体 ID）
- 校验码：**CRC-16/X25**，初值 `0xFFFF`，对 `payload` 逐字节累积后，再并入 `MAVLINK_MESSAGE_CRCS[msgid]` 种子值
- 校验种子表 `MAVLINK_MESSAGE_LENGTHS` / `MAVLINK_MESSAGE_CRCS` 对 **MR 飞机** 与 **X8 飞机** 存在两套不同定义（文档已分别给出）

### 2.2 按功能分组

```
Skylink 消息
├─ 链路管理
│   └─ 0   心跳（离线判定阈值 5s）
├─ 遥测状态（周期性广播，地面站主刷新源）
│   ├─ 1   系统状态   1Hz   ← 地面站以它为准刷新 0/1/180 三条
│   ├─ 180 导航消息   1Hz
│   ├─ 84  附加信息   1Hz
│   └─ 186 健康状态   1Hz
├─ 参数管理（握手式）
│   └─ 20 读参数 / 21 请求列表 / 22 上报 / 23 设置
├─ 航线任务（握手式 + 周期上报）
│   ├─ 常规：44 总数 → 40 请求 → 39 下发 → 47 回复
│   ├─ RTK ：83 请求 → 82 下发
│   └─ 状态：42 当前航点（0.5Hz）
├─ 指令控制
│   ├─ 76/77 复杂命令（带参数）+ 应答
│   └─ 78/79 简单命令（无参数）+ 应答
├─ 设备信息（条件广播，需 CommandLong 确认停播）
│   ├─ 183 系统信息
│   ├─ 184 电池信息
│   └─ 185 电调信息
├─ 场景扩展
│   └─ 138 近场通知（进近 <1km 时广播）
└─ 诊断
    └─ 253 调试打印 / 181-182 错误码
```

### 2.3 三条"设备信息"广播的握手逻辑

183 / 184 / 185 三个消息采用**同一套确认停播机制**：

1. 飞控上电 **40s 内** 且处于 **DISARM** 状态时，周期性（0.5Hz）广播
2. 后台收到后用 **CommandLong** 告知飞控"已收到"
3. 飞控回 ACK，并**停止**该消息广播

两个版本的差异：

| 机型/版本 | 广播策略 |
|---|---|
| 方舟（Ark） | 上电 40s 内 + DISARM，且保证 SYS_INFO 先于 ESC_INFO 被收到 |
| 魔鬼鱼（MR/外售） | 只要收到地面站 CommandLong 请求，就广播一次 |

### 2.4 关键消息要点

**1 号 SYS_STATUS** — 地面站状态刷新的主数据源，广播内容：
- 电压 mV / 电流 mA / 剩余电量 mAh / SOC%
- `Navi_mode` = `(fm_status << 5) | (navi_status & 0x0f)`
  - fm_status：0 Normal / 1 航线 / 2 备降 / 3 返航 / 4 迫降 / 5 低电量迫降 / 6 航线执行完毕 / 7 低电量迫降
  - navi_status：0 INIT / 1 VG / 2 AHRS / 3 VEL / 4 DR / 5 ALIGN / 6 POS / 7 RTK
- `Vehicle_status` = `(Main_Mode << 6) | Flight_Status`
  - main_mode：0 位置 / 1 姿态 / 2 手动
  - flight_status：0 disarm … 23 视觉朝向调整（详见原文档）

**44 号 MISSION_COUNT** — 复用帧保留位：

| Bit13…10 | Bit9…6 | Bit5…2 | Bit1…0 |
|---|---|---|---|
| 备降点 logo id | 起飞点 logo id | 降落点 logo id | 无人柜 id |

**82/83 RTK 航点** — Seq 编码规则（一帧装 2 个点）：

| Seq 范围 | 含义 |
|---|---|
| 0 | 起降点（X1/Y1=起飞点，X2/Y2=降落点） |
| 1 ~ 100 | 备降点 0~199 |
| 101 ~ 150 | 航点 0~99 |
| 其他 | 备用 |

无效值约定：`X2/Y2 = 0x7FFFFFFF`（无第二点）、`Z = -1000`（非航点段）、`Frame = 0xFF`（非航点段）

**76 号 COMMAND_LONG 常用命令码**

| 功能 | Command | param1 | param2 | param3 |
|---|---|---|---|---|
| 航前检查 | 520 | 1~7（电机/尾推/副翼/升降/方向舵/复位/自动检测） | 视子项 | - |
| 信息获取 | 245 | 183 系统信息 / 184 BMS / 185 ESC | - | - |
| 起飞 | 22 | - | - | - |
| 降落 | 21 | - | - | - |
| 悬停/盘旋 | 17 | - | - | - |
| 返航 | 20 | >30 直线返航；≤30 原路返航 | - | - |
| 备降 | 56 | - | - | - |
| 恢复 | 30 | - | - | - |
| 上锁/解锁 | 400 | >30 解锁；-30~0 开伞；<-30 上锁 | - | - |
| 指令二次确认 | 405 | 20:ARM / 21:TAKEOFF | - | - |
| 视觉 logo | 450 | 起飞点 logo(0~65535) | 降落点 logo | 备降点 logo |

### 3.1 精准地面点扩充（2024-06）—— 130/131 → 140/141

**背景问题**
- 问1：131 消息新的数据组成及用法需变更说明
- 问2：地面站和后台如何对 FCC6.0 控制的飞机发送 130/131 消息（讨论了 4 种方法）

**4 种候选方案**

| 方案 | 做法 | 评审 |
|---|---|---|
| 方法1 | 用版本的最高字段区分 | 标记为 Y（倾向） |
| 方法2 | key 999 功能支持查询 | - |
| 方法3 | 沿用原 107，发送备降点请求时给特殊错误码 | - |
| 方法4 | 全部替换成新的消息 | - |

**最终结论（2024-06-12）**
1. 原有地面精准点传输 **130/131 保持不变**，另扩充一对 **140/141** 替代当前传输
2. 底层支持 140/141 后，原有 130/131 交互**会报错**
3. FCC 和 AMOS 版本里的特殊字段新加一个定义，**暂定 2**
4. **机型 uav_type 是否变更待讨论**（未决）

**140 MISSION_EXT_EXACTLY_CFG（扩充精准地面点设置请求）** REQ 4B / RSP 1B

| Offset | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | U32 | type_new | 坐标点类别 **2**=扩充精准地面点；航线 id 最小 1、最大 8 |
| 4 | U16 | total_num | 总航点数 |
| 10 | U8 | Frame | MAV_FRAME_GLOBAL…见附件四 |
| 10 | U8 | reserved | 预留 |
| 20 | U32 | identity | 唯一身份 ID |
| 24 | U32 | crc | CRC 校验码 |

RSP：type_new(U32) + error_code(U8)

**141 MISSION_EXT_EXACTLY_ITEM（扩充精准地面点包发送）** 变长

| Offset | 类型 | 字段 | 说明 |
|---|---|---|---|
| 1 | U8 | flag | bit1:0 → 00b 首包 / 01b 中间包 / 10b 末包 / 11b 单包；高 6 位保留 |
| 2 | U8 | item | 当前帧包含航点个数 |
| 3 | U16 | seq | 本包起始航点序号，从 0 开始 |
| 4 | U32 | type_new | 航线类别 |
| - | I32 | Latitude_gps | 纬度 1e-7 |
| - | I32 | longitude_gps | 经度 1e-7 |
| - | F32 | altitude_gps_ground | 地面海拔高，无效值 **-2000** |
| - | U32 | vision_code | 视觉识别码：0 圆形/1 三角形/2 矩形/3 菱形/4-254 二维码，无效值 0xFFFFFFFF |
| - | F32 | height_sky_safe | 空中安全海拔高度，无效值 -2000 |
| - | U8 | pcmd | payload 解释命令码 |
| - | U8 | plen | payload 有效字节长度 |
| - | U8_64 | payload[64] | 变长，plen=0 时可为空，最大 64 byte |

**空值约定**：`latitude = 1000000000`、`longitude = 1900000000`、`altitude = -2000.0`

**航点语义约定**
- 默认第 1 个点 = 起飞点
- 默认第 2 个点 = 降落点
- 默认第 3 个点起 = 用户自定义备降点，作为 1 号备降点给飞控

**130/131 vs 140/141 字段对比**

| 维度 | 131（旧） | 141（新） |
|---|---|---|
| 坐标系 | GPS + RTK 双套（各 lat/lon/alt） | 仅 GPS 一套 |
| 高度字段 | altitude_gps_ground + altitude_rtk_ground + altiude_sky | altitude_gps_ground + height_sky_safe |
| 视觉码 | U8_8 vision_code | U32 vision_code（带类型枚举+无效值） |
| 扩展能力 | 无 | **pcmd + plen + payload[64] 变长扩展** |
| 其他 | LandHead(U16 降落机头角)、reserved | 移除 LandHead，改为扩展位 |

**Payload 填充方案**

| 方案 | pcmd/plen 分布 | 最大长度 | 多组 pcmd | 结论 |
|---|---|---|---|---|
| 方案一 | 0/0、1/12、2/14、3/16、4/18、5/22 | 22+2 = **24 byte** | 不允许 | - |
| 方案二 | 0/0、1/12、2/2、3/2、4/2、5/4 | 22+5×2 = **32 byte** | 允许 | ✅ **暂定采用（2024-06-26）** |

保留 1 字节 plen 的考虑：从机需内建 pcmd 长度查找表，校验主机 plen 是否正确以决定是否解析 payload。

### 3.2 未知消息回复约定（2024-06-24）

FCC 机型/版本差异导致消息支持度不同。**旧版本无法解析后续版本新定义的 MSGID**，统一约定：

> 收到未知 MSGID 时，返回 `LEN = 0`（无 payload）、`FTYPE` 定义为**无定义类型**的消息。

### 3.4 系统内部评估监视消息 151（2024-08-13）

**需求来源**：导航系统需在外场运营环境监视新算法运行状态（如磁力计在线评估校准可靠性），要求**地面站无感**，不得通过故障码通知。

- 后台仅做格式化记录，变量名可重命名；需同时关联记录其他航班数据
- 发送频率 **≤ 1 Hz**
- 变长帧，**最长不超过 204 字节**

| Offset | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | U16 | component_id | 组件 id，发送方内部约定 |
| 1 | U16 | payload_len | 消息长度 |
| 2 | U8_N | payload[200] | 消息内容 |

| component_id | payload 定义 |
|---|---|
| 0 | 错误的组件 id |
| 1 | 内部监视组件消息 1，长度 **48 byte**：`Float[4] + Int32[4]` |
| 2 | 待定义 |

**结论（2024-08）**：FCC 内部仅需定义好内部组件 ID 并把数据流发给后台，具体数据格式由后台添加解析配置。

### 3.6 SDK 载荷信息（2024-11-18）

地面站开发巡检项目需获取载荷基本信息，采用**查询方式**获取。

**Skylink【111】key = 210~215** → `sdk_payload_info` 消息

```c
typedef struct sdk_payload_info_s {
    uint8_t  type;        // 第三方载荷总数及类别
    uint8_t  status;      // 当前载荷状态
    uint16_t vendor_code; // 厂家及产品型号
    uint8_t  sn[32];      // 载荷识别码
} sdk_payload_info_t;
```

| 字段 | 说明 |
|---|---|
| type | 高 4bit = 第三方载荷总数（约定 ≤5）；低 4bit = 载荷类别，**1=光电吊舱**，其余未定义 |
| status | 当前载荷状态 |
| vendor_code | **1 = 成都浩孚 TS01GD**，其余未定义 |
| sn[32] | 产品唯一识别码，从低 byte 起排，全 0 表示无此码 |

> 示例：成都浩孚 TS01GD 产品编码 `0x4536` → `SN[31…2]` 全 0，`SN[0]=0x45`、`SN[1]=0x36`

### 3.7 飞机端激活码（2026-01-08）

**管控要求**

| 场景 | 规则 | 管控方 |
|---|---|---|
| 运营场景 | 未激活不允许解锁及起飞 | 地面站 |
| 生产测试 | 允许未激活但需飞行（例外场景） | - |
| 未激活飞机 | 不允许解锁 | **FCC** |
| 已激活飞机 | 无法修改飞机 SN | **FCC** |
| 激活条件 | 必须有非零 SN；改变 link_id **不影响**激活状态（已确定） | - |
| 工厂模式 | 不管控激活状态；**不允许激活** | - |
| 非工厂模式 | 未激活不允许解锁 | - |
| 参数清空 | 恢复出厂（未激活） | - |

飞机端提供 **【激活】/【注销】** 两个操作接口。

**新增点 1：105 消息新增 0x08-0xF1 命令（激活命令）**

| 命令 | 参数有效长度 | 内容 |
|---|---|---|
| 0x08 本机模块配置 / 0xF1 | 32 byte | Pram[0] 激活动作：**0** 取消激活、**1** 正式激活、**2** 临时激活（出厂测试）<br>Pram[1] 预留 / Pram[2] 预留<br>Pram[3] SN 码有效长度（最长 28）<br>Pram[4…31] SN 码数据 |

> 正式激活/取消激活的**时间戳必须有效**，须 > `1735689600`（2025-01-01 00:00:00）
> SN 码不一致或时间戳无效 → 命令出错，**不改变当前激活状态**

**新增点 2：激活状态上报**

- 原方案：103 消息新增 TYPE = 13
- **改为**：**111 消息 key = 1000 查询**，3 秒/次

```
变量名：active_state   类型：U8
0：未激活   1：已激活   2：临时激活
开机正常启动后每隔 3 秒定频上报
```

**新增点 3：飞机端新增 3 个参数**

| 参数名 | 默认值 | 取值 |
|---|---|---|
| SYS_ACTIVE_STATE | 0 未激活 | 0 未激活 / 1 已激活 / 2 临时激活 |
| SYS_ACTIVE_TIME | 0 | 激活或取消激活时的 UTC 时间戳 |
| SYS_FACTORY_MODE | 0 工厂模式 | 0 工厂模式 / 1 非工厂模式（运营或外售） |

**配套变更**
- 功能 list 里添加"激活功能"
- 111 key-value 添加 `uas_oc` 值查询

### 3.8 通用模块扩展消息 145（2026-03-16）

**定位**：飞机内部新增、但不适合放进 103 消息的内容统一走此通道。

## 六、阅读建议

1. **先补基线**：v2.0 评审记录是"增量+结论"，脱离 102/103/105/107/111/130/131 的基线定义无法落地，优先向协议负责人索取中间版本。
2. **注意方向性约定**：v1.5.0 中 UP = 机载→QC，DOWN = QC→机载；v2.0 新增消息改用 REQ/RSP/MSG 三行标注，语义不同，勿混用。
3. **注意两个"111"**：v1.5.0 无 111 消息定义，v2.0 中 111 是 key-value 查询通道（key 210~215 载荷、key 1000 激活状态）。
4. **时间跨度提示**：v2.0 记录跨越 2024-06 ~ 2026-07，其中 2026 年的条目（激活码、运行识别广播、SN 配置）已涉及 GB46750-2025 强制标准合规，优先级最高。
