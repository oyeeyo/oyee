# 03 - 数据源管理模块

> **阅读目标**：理解 SQLBot 如何连接和管理多种数据库，以及连接池管理机制
> **核心文件**：`backend/apps/db/db.py`、`backend/apps/datasource/`

---

## 1. 支持的数据源类型

SQLBot 支持连接多种数据库，由 `apps/db/constant.py` 中的 `DB` 枚举定义：

| 数据库类型 | 标识 | 连接方式 | 驱动 |
|-----------|------|---------|------|
| MySQL | `mysql` | SQLAlchemy | pymysql |
| PostgreSQL | `pg` | SQLAlchemy | psycopg2 |
| Oracle | `oracle` | SQLAlchemy | oracledb |
| SQL Server | `sqlServer` | 原生驱动 | pymssql |
| ClickHouse | `ck` | SQLAlchemy | clickhouse-sqlalchemy |
| DM（达梦）| `dm` | 原生驱动 | dmPython |
| Doris | `doris` | 原生驱动 | pymysql |
| StarRocks | `starrocks` | 原生驱动 | pymysql |
| Redshift | `redshift` | 原生驱动 | redshift_connector |
| KingBase | `kingbase` | 原生驱动 | psycopg2 |
| Hive | `hive` | 原生驱动 | pyhive |
| Elasticsearch | `es` | HTTP API | elasticsearch |
| Excel | `excel` | SQLAlchemy | 内存 PostgreSQL |

> 💡 连接方式分两种：
> - **SQLAlchemy**：使用 SQLAlchemy ORM 管理连接
> - **原生驱动**：直接使用数据库驱动连接（因为 SQLAlchemy 不支持或支持不好）

## 2. 数据源数据模型

### 2.1 CoreDatasource — 数据源表

```python
# apps/datasource/models/datasource.py

    table_relation: List  # 表关联关系（JSONB）
    embedding: str        # 向量嵌入（用于语义匹配数据源）
```

### 2.2 DatasourceConf — 连接配置

`configuration` 字段解密后的结构：

```python
class DatasourceConf(BaseModel):
    host: str          # 主机地址
    port: int          # 端口
    username: str      # 用户名
    password: str      # 密码
    database: str      # 数据库名
    extraJdbc: str     # 额外连接参数（如 "useSSL=false&charset=utf8"）

    timeout: int = 30  # 连接超时（秒）

```

### 2.3 CoreTable / CoreField — 表和字段

```python
class CoreTable(SQLModel, table=True):
    __tablename__ = "core_table"

class CoreField(SQLModel, table=True):
    __tablename__ = "core_field"

    field_type: str       # 字段类型（varchar/int/datetime...）
    field_comment: str    # 字段注释
    custom_comment: str   # 用户自定义注释
    field_index: int      # 字段排序
```

## 3. 数据库连接流程

### 3.1 连接 URL 构建

`apps/db/db.py` 中的 `get_uri()` 函数根据数据库类型构建不同的连接 URL：

```python
def get_uri_from_config(type: str, conf: DatasourceConf) -> str:
    if type == "mysql":
        # mysql+pymysql://user:pass@host:port/db
        return f"mysql+pymysql://{conf.username}:{conf.password}@{conf.host}:{conf.port}/{conf.database}"

    elif type == "pg":
        # postgresql+psycopg2://user:pass@host:port/db
        return f"postgresql+psycopg2://{conf.username}:{conf.password}@{conf.host}:{conf.port}/{conf.database}"

    elif type == "oracle":
        # oracle+oracledb://user:pass@host:port?service_name=db
        return f"oracle+oracledb://{conf.username}:{conf.password}@{conf.host}:{conf.port}?service_name={conf.database}"

    # ... 其他数据库类型类似
```

### 3.3 连接池管理（LRU 策略）

```python
class ConnectionPoolManager:
    def __init__(self, max_pools=500):
        self._pools = OrderedDict()  # 有序字典实现 LRU
        self._lock = threading.Lock()  # 线程安全

    def get_pool(self, ds, **db_config):
        with self._lock:
            if ds.id in self._pools:
                # 已存在 → 移到末尾（最近使用）
                self._pools.move_to_end(ds.id)
                return self._pools[ds.id]

            if len(self._pools) >= self.max_pools:
                # 超过上限 → 淘汰最久未使用的（头部）
                oldest_id, oldest_pool = self._pools.popitem(last=False)
                oldest_pool.close()

            # 创建新连接池
            engine = get_engine(ds, use_pool=True)
            new_pool = sessionmaker(bind=engine)
            self._pools[ds.id] = new_pool
            return new_pool
```

> 💡 **LRU（Least Recently Used）**：最久未使用的连接池会被自动关闭和淘汰，避免内存泄漏。

## 4. 元数据获取

SQLBot 需要从用户的数据源中获取表结构信息，用于构建 Prompt。不同数据库的查询 SQL 不同：

### 4.1 获取表列表

```python
# apps/db/db_sql.py 中为每种数据库定义了不同的查询

# MySQL:
SELECT table_name, table_comment
FROM information_schema.tables
WHERE table_schema = :param

# PostgreSQL:
SELECT tablename, ''
FROM pg_tables
WHERE schemaname = :param

# Oracle:
SELECT table_name, comments
FROM user_tables LEFT JOIN user_tab_comments USING(table_name)
```

### 4.2 获取字段列表

```python
# MySQL:
SELECT column_name, data_type, column_comment
FROM information_schema.columns
WHERE table_schema = :param1 AND table_name = :param2

# PostgreSQL:
SELECT column_name, data_type, ''
FROM information_schema.columns
WHERE table_schema = :param1 AND table_name = :param2
```

## 5. SQL 安全检查

`exec_sql()` 中的 `check_sql_read()` 函数确保只执行只读查询：

```python
def check_sql_read(sql: str, ds) -> tuple[bool, str]:
    # 1. 检查首关键字
    allowed_read_commands = {"SELECT", "WITH", "SHOW", "DESCRIBE", "EXPLAIN"}
    denied_write_commands = {"INSERT", "UPDATE", "DELETE", "CREATE", "DROP", "ALTER", ...}

    # 2. 使用 sqlglot 解析 SQL，检查危险函数
    statements = sqlglot.parse(sql, dialect=dialect)
    for stmt in statements:
        # 检查是否有危险函数（如 LOAD_FILE, xp_cmdshell 等）
        for func in stmt.find_all(exp.Anonymous):
            if func.name.upper() in dangerous_functions:
                return False, f"SQL contains dangerous function: {func.name}"

        # 检查是否有写操作 AST 节点
        if isinstance(stmt, (Insert, Update, Delete, Create, Drop, Alter)):
            return False, f"SQL contains write operation"
```

## 7. 表与字段的管理

管理员在配置数据源后，可以：
1. **勾选/取消表**：选择哪些表参与 NL2SQL（`CoreTable.checked`）
2. **勾选/取消字段**：选择哪些字段参与 NL2SQL（`CoreField.checked`）
3. **添加自定义注释**：帮助 LLM 理解表/字段的业务含义（`custom_comment`）

```
数据源 "销售数据库" (MySQL)
├── 表: sales_order ✓
│   ├── 字段: order_id (INT) ✓ — "订单ID"
│   ├── 字段: amount (DECIMAL) ✓ — "订单金额"
│   ├── 字段: status (VARCHAR) ✓ — "订单状态：pending/paid/shipped"
│   └── 字段: internal_code (VARCHAR) ✗ — （不参与问答）
├── 表: customer ✓
│   ├── 字段: customer_name (VARCHAR) ✓
│   └── 字段: region (VARCHAR) ✓ — "所属区域：华东/华南/华北..."
└── 表: system_log ✗ — （不参与问答）
```

这些信息最终会被组装到 Prompt 的 `<m-schema>` 标签中，告诉 LLM 有哪些表和字段可用。

## 小结

1. **多数据库支持**：通过 `db.py` 统一管理 12+ 种数据库的连接和查询
2. **连接池 LRU 管理**：最多 500 个连接池，自动淘汰最久未使用的
3. **元数据获取**：针对不同数据库使用不同的 SQL 查询表结构
4. **安全检查**：使用 sqlglot 解析 SQL，防止写操作和危险函数
5. **表/字段管理**：管理员可以勾选参与问答的表和字段，添加自定义注释
