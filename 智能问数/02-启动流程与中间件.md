# 02 - 启动流程与中间件

> **阅读目标**：理解应用从启动到处理请求的全过程，掌握中间件的拦截链

---

## 1. 应用启动流程

### 入口文件：`backend/main.py`

应用启动分两个阶段：**创建 FastAPI 实例** 和 **生命周期事件**。

```
┌─────────────────────────────────────────────────────┐
│               uvicorn.run("main:app")               │
│                     ↓                               │
│         1. 导入 main.py，创建 FastAPI 实例            │
│                     ↓                               │
│         2. 注册中间件（从外到内执行）                   │
│                     ↓                               │
│         3. 注册路由 (api_router)                      │
│                     ↓                               │
│         4. 注册异常处理器                              │
│                     ↓                               │
│         5. 触发 lifespan 事件（启动）                  │
│                     ↓                               │
│         6. 开始监听 HTTP 请求                          │
└─────────────────────────────────────────────────────┘
```

### 1.1 FastAPI 实例创建

```python
# backend/main.py

app = FastAPI(
    title=settings.PROJECT_NAME,          # "SQLBot"
    openapi_url=f"{settings.CONTEXT_PATH}/openapi.json",
    generate_unique_id_function=custom_generate_unique_id,
    lifespan=lifespan,     # ⭐ 生命周期管理器（启动/关闭事件）
    docs_url=None,         # 禁用默认 /docs
    redoc_url=None         # 禁用默认 /redoc
)
```

> 💡 `lifespan` 是 FastAPI 推荐的启动/关闭事件管理方式（替代了旧的 `on_event("startup")`）。

### 1.2 生命周期事件（lifespan）

这是**最关键的启动逻辑**，按顺序执行：

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    # ===== 启动阶段（按顺序执行）=====

    # 1. 数据库迁移：自动执行 alembic 迁移脚本
    run_migrations()

    # 2. 初始化缓存（SQLBot 内部缓存）
    init_sqlbot_cache()

    # 3. 初始化动态 CORS（根据助手配置动态添加允许的域名）
    init_dynamic_cors(app)

    # 4. 初始化术语表的向量嵌入（后台线程）
    init_terminology_embedding_data()

    # 5. 初始化数据训练（SQL示例）的向量嵌入
    init_data_training_embedding_data()

    # 6. 初始化表和数据库的向量嵌入
    init_table_and_ds_embedding()

    # 7. 清理 xpack 缓存
    await sqlbot_xpack.core.clean_xpack_cache()

    # 8. 异步加密模型密钥（保护敏感信息）
    await async_model_info()

    # 9. xpack 监控
    await sqlbot_xpack.core.monitor_app(app)

    yield  # ← 应用在此开始处理请求，运行中...

    # ===== 关闭阶段（yield 之后执行）=====
    shutdown_resources()
```

> 💡 `@asynccontextmanager` + `yield` 是 Python 的异步上下文管理器模式。`yield` 之前的代码在启动时执行，之后的在关闭时执行。

### 1.3 初始化逻辑解读

| 启动步骤 | 做了什么 | 为什么需要 |
|---------|---------|-----------|
| `run_migrations()` | 执行 Alembic 迁移，确保数据库表结构是最新的 | 自动建表/更新表结构 |
| `init_sqlbot_cache()` | 预热内部缓存 | 提高首次请求的响应速度 |
| `init_dynamic_cors()` | 从数据库读取助手配置，动态添加 CORS 允许的域名 | 嵌入式助手需要跨域 |
| `init_*_embedding()` | 为缺少向量嵌入的数据计算并填充 | 确保语义搜索正常工作 |
| `async_model_info()` | 对存储的模型密钥和地址进行加密 | 保护敏感信息 |

> 💡 `@SingleWorkerGuard.once` 装饰器确保在多 worker 部署时，初始化逻辑只执行一次。

## 2. 中间件链（请求拦截流水线）

### 2.1 中间件注册顺序

中间件的注册顺序决定了请求的处理顺序。**注意：后注册的中间件先执行**（洋葱模型）：

```python
# 注册顺序（从后到先执行）：
app.add_middleware(TokenMiddleware)           # 3️⃣ 认证（最后注册，最先执行）
app.add_middleware(ResponseMiddleware)        # 2️⃣ 统一响应格式
app.add_middleware(RequestContextMiddleware)  # 1️⃣ 请求上下文（记录请求信息）
app.add_middleware(RequestContextMiddlewareCommon)  # 0️⃣ 通用请求上下文
```

### 2.2 请求处理流程图

```
客户端请求
    │
    ▼
┌──────────────────────────────────────┐
│  RequestContextMiddlewareCommon      │  ← 最先执行
│  记录请求开始时间、请求 ID 等          │
└──────────────┬───────────────────────┘
               │
               ▼
┌──────────────────────────────────────┐
│  RequestContextMiddleware            │
│  记录请求详情（操作人、模块等）         │
└──────────────┬───────────────────────┘
               │
               ▼
┌──────────────────────────────────────┐
│  ResponseMiddleware                  │
│  统一响应格式、异常处理                │
└──────────────┬───────────────────────┘
               │
               ▼
┌──────────────────────────────────────┐
│  TokenMiddleware     ⭐ 最重要！       │
│  验证用户身份（JWT / API Key / 助手）   │
│  验证失败 → 返回 401                  │
│  验证成功 → 将用户信息放入 request.state │
└──────────────┬───────────────────────┘
               │
               ▼
         路由处理器（API 函数）
               │
               ▼
         返回响应给客户端
```

### 2.3 TokenMiddleware 详解（核心认证逻辑）

这是最重要的中间件，负责验证每个请求的身份。支持三种认证方式：

```python
class TokenMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        # 1. OPTIONS 请求和白名单路径直接放行
        if self.is_options(request) or whiteUtils.is_whitelisted(request.url.path):
            return await call_next(request)

        # 2. 检查 API Key 认证（X-SQLBOT-ASK-TOKEN）
        askToken = request.headers.get("X-SQLBOT-ASK-TOKEN")
        if askToken:
            validate_pass, data = await self.validateAskToken(askToken, trans)
            if validate_pass:
                request.state.current_user = data  # 用户信息注入到 request
                return await call_next(request)

        # 3. 检查助手认证（X-SQLBOT-ASSISTANT-TOKEN）
        assistantToken = request.headers.get(settings.ASSISTANT_TOKEN_KEY)
        if assistantToken:
            validator = await self.validateAssistant(assistantToken, trans)
            if validator[0]:
                request.state.current_user = validator[1]  # 用户信息
                request.state.assistant = validator[2]     # 助手信息
                return await call_next(request)

        # 4. 检查普通用户认证（X-SQLBOT-TOKEN）
        token = request.headers.get(settings.TOKEN_KEY)
        validate_pass, data = await self.validateToken(token, trans)
        if validate_pass:
            request.state.current_user = data
            return await call_next(request)

        # 5. 全部验证失败 → 返回 401
        return JSONResponse(status_code=401, content={"message": "认证失败"})
```

#### 三种认证方式对比

| 认证方式 | Header | Token 格式 | 使用场景 |
|---------|--------|-----------|---------|
| 普通用户 | `X-SQLBOT-TOKEN` | `Bearer <JWT>` | 前端 Web 界面登录 |
| 助手嵌入 | `X-SQLBOT-ASSISTANT-TOKEN` | `Assistant <JWT>` 或 `Embedded <JWT>` | 嵌入式问答助手 |
| API Key | `X-SQLBOT-ASK-TOKEN` | `SK <JWT>` | 第三方 API 调用 |

#### JWT Token 验证流程

```
Bearer eyJhbGciOiJIUzI1NiIs...
    │
    ▼
1. 分离 schema ("Bearer") 和 token 值
    │
    ▼
2. 用 SECRET_KEY 解码 JWT → 得到 payload
    │  payload = { "id": 用户ID, "exp": 过期时间, ... }
    │
    ▼
3. 从数据库查询用户信息
    │
    ▼
4. 检查：用户是否存在？是否禁用？是否关联了工作空间？
    │
    ▼
5. 通过 → 返回 UserInfoDTO 对象
```

## 3. 路由注册

### 3.1 路由总入口

所有模块的路由在 `apps/api.py` 中统一注册：

```python
# backend/apps/api.py
api_router = APIRouter()
api_router.include_router(login.router)       # 登录
api_router.include_router(user.router)        # 用户管理
api_router.include_router(workspace.router)   # 工作空间
api_router.include_router(assistant.router)   # 助手
api_router.include_router(aimodel.router)     # AI 模型
api_router.include_router(terminology.router) # 术语表
api_router.include_router(data_training.router) # 数据训练
api_router.include_router(datasource.router)  # 数据源
api_router.include_router(chat.router)        # ⭐ 智能对话
api_router.include_router(dashboard_api.router) # 仪表盘
api_router.include_router(mcp.router)         # MCP 协议
# ... 更多模块
```

### 3.2 路由前缀

在 `main.py` 中给总路由添加前缀：

```python
app.include_router(api_router, prefix=settings.API_V1_STR)
# settings.API_V1_STR = "/api/v1"
```

所以最终的路由路径是：
- 登录：`POST /api/v1/login`
- 提问：`POST /api/v1/chat/question`
- 数据源列表：`GET /api/v1/datasource/list`
- ...

## 4. 依赖注入系统

FastAPI 的依赖注入是贯穿整个请求处理的核心机制：

```python
# common/core/deps.py

# 数据库 Session 依赖
SessionDep = Annotated[Session, Depends(get_session)]

# 当前用户依赖（从中间件获取）
CurrentUser = Annotated[UserInfoDTO, Depends(get_current_user)]

# 当前助手依赖
CurrentAssistant = Annotated[AssistantHeader, Depends(get_current_assistant)]

# 国际化依赖
Trans = Annotated[I18n, Depends(get_i18n)]
```

**工作原理**：

```python
async def get_current_user(request: Request) -> UserInfoDTO:
    return request.state.current_user  # 从 TokenMiddleware 设置的用户信息
```

当 API 函数声明参数 `current_user: CurrentUser` 时：
1. FastAPI 自动调用 `get_current_user()`
2. 从 `request.state.current_user` 获取 `TokenMiddleware` 注入的用户对象
3. 如果中间件验证失败，请求到不了这里（已经返回 401 了）

## 5. 异常处理

在 `main.py` 中注册了全局异常处理器：

```python
app.add_exception_handler(StarletteHTTPException, exception_handler.http_exception_handler)
app.add_exception_handler(Exception, exception_handler.global_exception_handler)
```

这确保所有未捕获的异常都会返回统一格式的错误响应，而不是暴露内部错误信息。

---

## 小结

1. **启动流程**：`main.py` → 创建 FastAPI → 注册中间件/路由 → `lifespan` 执行初始化（迁移、缓存、嵌入等）
2. **中间件链**：TokenMiddleware 是核心，负责三种认证方式的验证，验证通过后将用户信息注入 `request.state`
3. **路由注册**：所有模块路由在 `apps/api.py` 汇聚，统一前缀 `/api/v1`
4. **依赖注入**：`SessionDep`, `CurrentUser`, `CurrentAssistant` 等让 API 函数无需手动获取数据库连接和用户信息
