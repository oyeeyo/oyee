## 1. 技术栈一览

| 技术 | 版本 | 在本项目中的角色 |
|------|------|-----------------|
| **Python** | 3.11 | 后端开发语言 |
| **FastAPI** | ≥0.115 | Web 框架，提供 API 接口，自带 OpenAPI 文档 |
| **SQLModel** | ≥0.0.21 | ORM 框架（= SQLAlchemy + Pydantic），用于数据库操作 |
| **Alembic** | ≥1.12 | 数据库迁移工具，管理表结构变更 |

| **uvicorn** | - | ASGI 服务器，运行 FastAPI 应用 |

### 依赖管理

项目使用 `pyproject.toml`（而非传统的 `requirements.txt`）管理依赖，使用 `uv` 作为包管理器：

```toml
# backend/pyproject.toml
[project]
name = "sqlbot"
version = "1.10.0"
requires-python = "==3.11.*"
dependencies = [
    "fastapi[standard]<1.0.0,>=0.115.12",
    "sqlmodel<1.0.0,>=0.0.21",
    "langchain>=0.3,<0.4",
    ...
]
```

## 3. 每个业务模块的分层结构

每个业务模块（如 `chat/`, `datasource/`）都遵循统一的分层架构：

```
模块目录/
├── api/            # API 层（Controller）
│   └── xxx.py      # 定义路由（@router.get/post/delete）
│                     接收请求参数，调用 crud 层，返回响应
│
├── crud/           # CRUD 层（Service）
│   └── xxx.py      # 业务逻辑：数据库查询、数据处理
│                     被 api 层调用
│                     注意：项目中有些地方写的是 "curd"（拼写错误，但已习惯）
│
├── models/         # 数据模型层（Model）
│   └── xxx.py      # SQLModel 表定义 + Pydantic Schema
│                     定义数据库表结构和请求/响应数据格式
│
└── schemas/        # 请求/响应 Schema（部分模块有）
    └── xxx.py      # 独立的 Pydantic 模型，用于数据验证
```

**数据流向**：
```
请求 → api/ (接收参数, 验证权限)
         → crud/ (业务逻辑, 数据库操作)
              → models/ (ORM 模型, 查询数据库)
         ← crud/ (返回处理结果)
     ← api/ (封装响应)
```

## 5. Python 基础概念补充

### 5.1 FastAPI 路由装饰器

```python
# 在 api/chat.py 中你会看到大量这样的代码：
@router.get("/list", response_model=List[ChatItem])
async def chats(session: SessionDep, current_user: CurrentUser):
    return list_chats(session, current_user)
```

解读：
- `@router.get("/list")` → 注册一个 GET 请求的路由，路径是 `/list`
- `response_model=List[ChatItem]` → 自动把返回值序列化为 JSON，并按 `ChatItem` 格式验证
- `async def` → 异步函数，不会阻塞服务器处理其他请求
- `session: SessionDep` → FastAPI 依赖注入，自动创建数据库 Session
- `current_user: CurrentUser` → FastAPI 依赖注入，从中间件获取当前登录用户

### 5.2 SQLModel 表定义

```python
# 在 models/datasource.py 中：
class CoreDatasource(SQLModel, table=True):
    __tablename__ = "core_datasource"    # 对应的数据库表名
    id: int = Field(sa_column=Column(BigInteger, primary_key=True))
    name: str = Field(max_length=128)
    type: str = Field(max_length=64)     # 数据库类型：mysql/pg/oracle...
    configuration: str = Field(sa_column=Column(Text))  # 连接配置（AES 加密）
    oid: int = Field(sa_column=Column(BigInteger()))    # 所属工作空间 ID
```

解读：
- `SQLModel` = 同时具备 SQLAlchemy 模型（操作数据库）和 Pydantic 模型（验证数据）的能力
- `table=True` → 表示这是一个数据库表（而非纯数据模型）
- `Field(sa_column=Column(...))` → 自定义 SQLAlchemy 列类型

### 5.3 依赖注入

```python
# 在 common/core/deps.py 中定义：
SessionDep = Annotated[Session, Depends(get_session)]
CurrentUser = Annotated[UserInfoDTO, Depends(get_current_user)]

# 在任何 API 函数中直接使用：
async def some_api(session: SessionDep, current_user: CurrentUser):
    # session 和 current_user 自动注入，无需手动获取
    ...
```

解读：
- `Depends()` → FastAPI 的依赖注入机制
- 每次请求时自动执行 `get_session()` / `get_current_user()` 获取对应对象
- 好处：代码简洁、易于测试、自动管理资源生命周期
