> **核心文件**：`backend/apps/chat/api/chat.py`、`backend/apps/chat/task/llm.py`
> **建议阅读时间**：30 分钟

## 1. 模块概述

智能对话模块是 SQLBot 的**心脏**。它负责：

```
用户自然语言提问 → 选择数据源 → 获取表结构 → 构建 Prompt → 调用 LLM →
生成 SQL → 安全检查 → 权限过滤 → 执行 SQL → 生成图表 → 返回前端
```

### 文件职责

| 文件 | 职责 |
|------|------|
| `chat/api/chat.py` | API 层：接收请求、参数校验、返回 SSE 流式响应 |
| `chat/task/llm.py` | ⭐ 核心引擎：`LLMService` 类，包含全部业务逻辑 |
| `chat/curd/chat.py` | 数据层：对话记录的 CRUD 操作 |
| `chat/models/chat_model.py` | 数据模型：Chat、ChatRecord、ChatLog 等 |

## 2. 数据模型

### 2.1 Chat — 对话（会话）

```python
class Chat(SQLModel, table=True):
    __tablename__ = "chat"
    id: int               # 主键
    brief: str            # 对话标题（自动生成或用户手动设置）
    datasource: int       # 绑定的数据源 ID（首次提问后自动绑定）
    engine_type: str      # 数据库类型
    oid: int              # 所属工作空间
    create_by: int        # 创建者
    origin: int           # 来源：0=网页对话, 1=API调用, 2=助手对话
```

### 2.2 ChatRecord — 对话记录（每一轮问答）

```python
class ChatRecord(SQLModel, table=True):
    __tablename__ = "chat_record"
    id: int                    # 主键
    chat_id: int               # 所属对话 ID
    question: str              # 用户问题
    sql: str                   # 生成的 SQL
    chart: str                 # 图表配置（JSON）
    data: str                  # SQL 执行结果（JSON）
    datasource: int            # 使用的数据源
    engine_type: str           # 数据库类型
    ai_modal_id: int           # 使用的 AI 模型 ID
    analysis_record_id: int    # 关联的分析记录
    predict_record_id: int     # 关联的预测记录
    regenerate_record_id: int  # 重新生成的原始记录 ID
    first_chat: bool           # 是否是第一轮（选数据源的轮次）
```

### 2.3 ChatLog — 操作日志（记录每次 LLM 调用）

```python
class ChatLog(SQLModel, table=True):
    __tablename__ = "chat_log"
    id: int
    type: TypeEnum             # 类型（CHAT）
    operate: OperationEnum     # 操作类型（生成SQL/生成图表/分析/预测...）
    pid: int                   # 关联的 ChatRecord ID
    ai_modal_id: int           # 使用的模型
    messages: list[dict]       # ⭐ 完整的 Prompt 消息（JSONB）
    reasoning_content: str     # LLM 的思考过程
    start_time: datetime       # 开始时间
    finish_time: datetime      # 结束时间
```

### 3.2 核心接口：`/chat/question`

```python
@router.post("/question")
@require_permissions(permission=SqlbotPermission(type='chat', keyExpression="request_question.chat_id"))
async def question_answer(session, current_user, request_question, current_assistant):
    question = ChatQuestion(chat_id=request_question.chat_id, question=request_question.question)
    return await question_answer_inner(session, current_user, question, current_assistant, embedding=True)
```

这个函数进入 `question_answer_inner()`，处理流程：

```
question_answer_inner()
    │
    ├─→ 检查快捷命令（/regenerate, /analysis, /predict）
    │     如果有 → 执行对应操作
    │     如果没有 → 进入正常提问流程
    │
    └─→ stream_sql()
          │
          ├─→ LLMService.create()     # 创建 LLM 服务实例
          ├─→ LLMService.init_record() # 创建对话记录
          └─→ LLMService.run_task_async() # 异步执行任务
```

### 3.3 SSE 流式输出

对话接口使用 **Server-Sent Events (SSE)** 向前端实时推送结果：

```python
# 返回 SSE 流
return StreamingResponse(llm_service.await_result(), media_type="text/event-stream")
```

SSE 消息格式：
```
data:{"type":"id","id":42}           ← 返回记录 ID
data:{"type":"question","question":"..."}  ← 回显问题
data:{"content":"SELECT...","type":"sql-result"}  ← SQL 生成过程（流式）
data:{"type":"info","msg":"sql generated"}  ← SQL 生成完成
data:{"content":"SELECT...","type":"sql"}  ← 格式化后的 SQL
data:{"content":"execute-success","type":"sql-data"}  ← SQL 执行成功
data:{"content":"...","type":"chart-result"}  ← 图表生成过程（流式）
data:{"content":"{...}","type":"chart"}  ← 最终图表配置
data:{"type":"finish"}               ← 完成
```

## 4. LLMService — 核心引擎（重点！）

`LLMService` 是整个 NL2SQL 流程的核心类，位于 `chat/task/llm.py`。

### 4.1 类结构概览

```python
class LLMService:
    ds: CoreDatasource              # 数据源
    chat_question: ChatQuestion     # 用户问题
    current_user: CurrentUser       # 当前用户
    record: ChatRecord              # 对话记录
    llm: BaseChatModel              # LangChain LLM 实例
    sql_message: List               # SQL 生成的 Prompt 消息
    chart_message: List             # 图表生成的 Prompt 消息
    current_logs: dict              # 操作日志

    # 核心方法
    def __init__()                  # 初始化：获取数据源、创建 LLM
    def init_messages()             # 构建 Prompt 消息
    def init_record()               # 创建对话记录
    def select_datasource()         # 选择数据源
    def generate_sql()              # 生成 SQL
    def generate_chart()            # 生成图表
    def execute_sql()               # 执行 SQL
    def generate_analysis()         # 数据分析
    def generate_predict()          # 数据预测
    def run_task()                  # ⭐ 主流程编排
```

### 4.2 创建过程（`__init__` + `create`）

```python
@classmethod
async def create(cls, session, current_user, chat_question, current_assistant, ...):
    # 1. 获取 AI 模型配置
    config = await get_default_config(specialized_model_id)

    # 2. 创建实例
    instance = cls(session, current_user, chat_question, ...)

    # 3. 读取系统参数（SQL行数限制、上下文轮数等）
    chat_params = await get_groups(session, "chat")
    # ... 设置 enable_sql_row_limit, base_message_round_count_limit

    return instance
```

`__init__` 中做了什么：
1. 查找 Chat 对象，验证权限
2. 获取数据源（CoreDatasource）
3. 查询历史日志（用于构建多轮对话上下文）
4. 创建 LLM 实例（通过 LLMFactory）
5. 获取上次 SQL 执行错误（用于纠错）

### 4.3 主流程：`run_task()`

这是整个 NL2SQL 的核心编排逻辑：

```python
def run_task(self, in_chat=True, stream=True, finish_step=GENERATE_CHART, return_img=True):
    _session = session_maker()  # 创建独立数据库会话

    # ========== 阶段 1：准备 ==========
    # 1.1 过滤术语表（根据问题语义匹配相关术语）
    self.filter_terminology_template(_session, oid, ds_id)

    # 1.2 过滤 SQL 示例（数据训练）
    self.filter_training_template(_session, oid, ds_id)

    # 1.3 过滤自定义 Prompt
    self.filter_custom_prompts(_session, CustomPromptTypeEnum.GENERATE_SQL, oid, ds_id)

    # 1.4 初始化消息（构建 Prompt）
    self.init_messages(_session)

    # 返回记录 ID 给前端
    yield {'type': 'id', 'id': self.record.id}

    # ========== 阶段 2：选择数据源（如果没有指定）==========
    if not self.ds:
        ds_res = self.select_datasource(_session)
        for chunk in ds_res:
            yield {'content': chunk, 'type': 'datasource-result'}

    # ========== 阶段 3：检查连接 ==========
    connected = check_connection(ds=self.ds)
    if not connected:
        raise SQLBotDBConnectionError('Connect DB failed')

    # ========== 阶段 4：生成 SQL ==========
    sql_res = self.generate_sql(_session)
    for chunk in sql_res:
        yield {'content': chunk, 'type': 'sql-result'}

    # ========== 阶段 5：安全检查 + 权限过滤 ==========
    sql, tables = self.check_sql(session=_session, res=full_sql_text, operate=...)

    # 表名安全检查
    actual_tables = extract_tables_from_sql(sql, ds_type=self.ds.type)
    unauthorized_tables = actual_tables - set(self.table_name_list)
    if unauthorized_tables:
        raise SingleMessageError(f"SQL contains unauthorized tables: {unauthorized_tables}")

    # 行级权限过滤
    if is_normal_user(self.current_user):
        sql_result = self.generate_filter(_session, sql, tables)
        if sql_result:
            sql = self.check_save_sql(session=_session, res=sql_result, ...)

    # 返回格式化 SQL
    yield {'content': sqlparse.format(sql, reindent=True), 'type': 'sql'}

    # ========== 阶段 6：执行 SQL ==========
    result = self.execute_sql(sql=sql)
    self.save_sql_data(session=_session, data_obj=result)
    yield {'content': 'execute-success', 'type': 'sql-data'}

    # ========== 阶段 7：生成图表 ==========
    chart_res = self.generate_chart(_session, chart_type, used_tables_schema)
    for chunk in chart_res:
        yield {'content': chunk, 'type': 'chart-result'}
    chart = self.check_save_chart(session=_session, res=full_chart_text)
    yield {'content': chart, 'type': 'chart'}

    # ========== 完成 ==========
    yield {'type': 'finish'}
```

## 5. Prompt 构建过程（init_messages）

`init_messages()` 是 Prompt 工程的核心，它将各种信息组装成 LLM 能理解的提示词：

```python
def init_messages(self, session):
    # 1. 选择相关表结构
    self.table_name_list = self.choose_table_schema(session)

    # 2. 构建 SQL 生成的 Prompt 消息序列
    self.sql_message = []

    # 2.1 系统提示词（角色定义 + 规则）
    _system = self.chat_question.sql_sys_question(ds_type, enable_sql_row_limit)
    self.sql_message.append(SystemPromptMessage(content=_system['system']))
    self.sql_message.append(HumanPromptMessage(content=_system['rules']))
    self.sql_message.append(AIPromptMessage(content='我已掌握所有规则...'))

    # 2.2 数据库 Schema
    self.sql_message.append(HumanPromptMessage(content=_system['schema']))
    self.sql_message.append(AIPromptMessage(content='我已确认数据库信息...'))

    # 2.3 自定义 Prompt（如果有）
    if _system.get('custom_prompt'):
        self.sql_message.append(HumanPromptMessage(content=_system['custom_prompt']))
        self.sql_message.append(AIPromptMessage(content='我已确认额外信息...'))

    # 2.4 术语表（如果有）
    if _system.get('terminologies'):
        self.sql_message.append(HumanPromptMessage(content=_system['terminologies']))
        self.sql_message.append(AIPromptMessage(content='我已确认术语信息...'))

    # 2.5 SQL 示例（数据训练，如果有）
    if _system.get('data_training'):
        self.sql_message.append(HumanPromptMessage(content=_system['data_training']))
        self.sql_message.append(AIPromptMessage(content='我已确认SQL示例...'))

    # 2.6 字段约束（如果用户确认了字段映射）
    if self._field_constraints_text:
        self.sql_message.append(HumanPromptMessage(content=self._field_constraints_text))
        self.sql_message.append(AIPromptMessage(content='我已确认字段映射...'))

    # 3. 添加历史对话上下文（多轮对话）
    last_rounds = get_last_conversation_rounds(last_sql_messages, rounds=count_limit)
    for msg in last_rounds:
        if msg['type'] == 'human':
            self.sql_message.append(HumanMessage(content=msg['content']))
        elif msg['type'] == 'ai':
            self.sql_message.append(AIMessage(content=msg['content']))
```

### Prompt 消息结构图

```
┌─────────────────────────────────────────┐
│  System: 角色定义 + SQL 生成规则          │  ← 告诉 LLM "你是谁"、"怎么做"
├─────────────────────────────────────────┤
│  Human: 详细规则                          │  ← SQL 规范、安全限制、输出格式
│  AI: "我已掌握所有规则"                    │  ← 预设确认
├─────────────────────────────────────────┤
│  Human: 数据库 Schema                     │  ← <m-schema>表结构</m-schema>
│  AI: "我已确认数据库信息"                  │  ← 预设确认
├─────────────────────────────────────────┤
│  Human: 术语表（如有）                    │  ← 业务术语解释
│  AI: "我已确认术语信息"                    │
├─────────────────────────────────────────┤
│  Human: SQL 示例（如有）                  │  ← 参考示例
│  AI: "我已确认SQL示例"                     │
├─────────────────────────────────────────┤
│  Human: 字段约束（如有）                  │  ← 用户确认的字段映射
│  AI: "我已确认字段映射"                    │
├─────────────────────────────────────────┤
│  Human: 历史问题 1                        │  ← 多轮对话上下文
│  AI: 历史回答 1                           │
│  Human: 历史问题 2                        │
│  AI: 历史回答 2                           │
├─────────────────────────────────────────┤
│  Human: 当前问题 + 当前时间               │  ← ⭐ 用户的实际问题
└─────────────────────────────────────────┘
```

## 6. 流式处理机制

### 6.1 异步执行 + 分块输出

```python
def run_task_async(self, ...):
    # 在线程池中异步执行任务
    self.future = executor.submit(self.run_task_cache, ...)

def run_task_cache(self, ...):
    # 将每个输出块放入缓冲区
    for chunk in self.run_task(...):
        self.chunk_list.append(chunk)

def await_result(self):
    # 前端持续读取缓冲区
    while self.is_running():
        chunk = self.pop_chunk()
        if chunk:
            yield chunk
```

### 6.2 LLM 流式输出处理

`process_stream()` 函数处理 LLM 的流式输出，包括思考过程的解析：

```python
def process_stream(res: Iterator[BaseMessageChunk], token_usage):
    for chunk in res:
        content = chunk.content
        reasoning_content = chunk.additional_kwargs.get('reasoning_content', '')

        # 解析 <think>...</think> 标签中的思考过程
        if '<think>' in content:
            in_thinking_block = True
        if '</think>' in content:
            in_thinking_block = False

        yield {
            'content': output_content,         # 实际输出内容
            'reasoning_content': reasoning_chunk # 思考过程（可选展示）
        }
```

## 8. 字段确认功能

当 LLM 选择的字段不准确时，用户可以手动确认字段：

```
1. 前端调用 /chat/field_candidates 获取候选字段
2. 用户在界面上选择正确的字段
3. 前端调用 /chat/confirm_fields_question 提交确认的字段映射
4. 系统将字段约束注入 Prompt，强制 LLM 使用指定字段
5. 重新走 NL2SQL 流程
```

```python
class ConfirmFieldsRequest(BaseModel):
    chat_id: int
    record_id: int
    question: str
    field_mapping: dict   # {原列名: 确认的字段名}
    field_tables: dict    # {原列名: 表名}
```

## 小结

1. **API 层**：`chat.py` 接收请求，处理快捷命令，返回 SSE 流
2. **核心引擎**：`LLMService` 编排整个 NL2SQL 流程（准备 → 选数据源 → 生成SQL → 安全检查 → 执行 → 生成图表）
3. **Prompt 构建**：将系统规则、Schema、术语、示例、历史对话、当前问题组装成多轮消息
4. **流式输出**：通过 SSE 实时推送 LLM 生成过程，用户体验更好
5. **安全机制**：表名权限检查 + SQL 安全检查 + 行级权限过滤
6. **多轮对话**：保留最近 N 轮历史对话作为上下文
